**Branches**: `master` is the 0.x stable line. `next` is the 1.0 line. `signals` is the 2.0 line, published under the `signals` dist-tag. Cherry-pick fixes from `master` → `next` as needed. Never merge `signals` into `next`.

## Architecture

Kensington is an HTML template library that generates HTML strings (or DOM elements) via nested method calls on a `Kensington` class instance.

### Generated vs. hand-written files

**`esm/kensington.js` and `esm/attributes.js` are generated**. Do not edit them directly. They are produced by `generate/bin/write-code-files.js` from:
- `generate/fetched-data/{html,svg,math}.json`. Spec data (fetched from HTML/SVG/MathML living standards)
- `@webref/css` (npm, runtime). CSS property and type syntax; used by `generate/parse-css-property-types.js` to derive TypeScript types and attribute validator values for SVG presentation attributes and CSS-sourced HTML element attributes
- `@webref/idl` (npm, runtime). WebIDL interface definitions; used by `generate/parse-idl-types.js` as a last-resort type fallback for attributes not typed by the HTML spec or CSS data
- `generate/build-javascript.js`. Template that emits the class body and attribute exports
- `generate/build-declarations.js`. Template that emits `types.d.ts`
- `generate/parse-data.js`. Normalizes spec data into the shape the builders expect
- `generate/parse-css-property-types.js`. Derives `{ value, type }` entries from `@webref/css` property syntax; resolves named type references and property references to extract keyword enums or numeric types
- `generate/parse-idl-types.js`. Derives `{ value, type }` entries from `@webref/idl` interface attribute types (boolean, integer, float IDL types map to Boolean/Number/[Number,String])

**`cjs/` is entirely generated** via Rollup from `esm/`. The `esm/` directory is the authoritative source.

### Hand-written source (`esm/`)

- `esm/index.js`. Package entry point; re-exports `Kensington` (default), `Signal`, `t`, `signal`, `computed`, `effect`, `isBrowser`, `renderForHydration`, `registerComponents`, and the HMR helpers `__kInstrument` and `hmrReplaceComponent`
- `esm/tag-classes/content-tag.js`. Base class for all HTML/SVG/MathML elements; handles attribute validation, content normalization, indentation, string serialization (`toString()`), and DOM creation (`toElement()`). `attributeValueIsValid` accepts `Signal` instances unconditionally (via `isKensingtonSignal()`). The actual value is only resolved at render time. `validateContent()` filters invalid items and reports via `showInvalid` (same `'off'`/`'warn'`/`'error'` contract as attribute validation. No unconditional throws). `toElement({ _inheritPersist? } = {})` collects cleanup functions from every signal attribute effect and signal content effect, then registers the element with `dom-tracker.js`. The cache check at the top of `toElement()` has four branches: (1) cached element is in the real DOM (`isConnected`) emits `showInvalid` and returns the cached node anyway; (2) `persist` is true, returns the cached node (effects are paused, not stopped); (3) disconnected and `#hasStaleDescendantBindings()` returns true, drops the cache and falls through to a fresh build; (4) disconnected with no stale bindings, returns the cached node. This covers never-mounted instances, static subtrees, stash-before-mount, non-reactive removed elements, and in-memory detached trees (the last case also emits `showInvalid` because `parentNode !== null`). The staleness walk asks each descendant tag with an `_isStaleAfterRemoval()` method whether its bindings were stopped on removal. `ContentTag` and `CommentTag` answer via their nulled `#domElement` (cleared by lifecycle's `onCleared`), `LiteralTag` via a `#reactiveStopped` flag flipped by the dom-tracker stop callback on its start anchor. Without this check, a static parent containing a signal-bearing descendant would reuse a cached element whose descendants' effects had been permanently stopped on removal. `persist` comes from `this.persist` (set in tag options) OR the `_inheritPersist` internal flag, which is passed as `{ _inheritPersist: persist }` when recursing into child `ContentTag` nodes (identified by `node._isKensingtonContentTag`) so descendants share the same pause/stop behaviour as the root. Without persist, removal calls `eff.stop()` (permanent); with persist, removal calls `eff.pause()` (temporary). When persist is active, `toElement()` also collects the effect objects themselves into a `resumables` array; on each reconnection the connect callback calls `eff.resume()` on each and wires the pauses back into the new stop chain so effects pause on removal and resume on re-insertion across unlimited cycles. `persist` is independent of `addConnectedCallback`. An element can pause/resume effects without any connected callbacks. `signalEffect()` calls pass a label string (the attribute name, `prop:X`, or `'(content)'`) to `lifecycle.signalEffect` for devtools display. The `prop` key is extracted from `options.attributes` in the constructor and stored in `this.prop`; `attributeIsValid` and `attributeValueIsValid` both accept `prop` (like `on`) so it is not flagged as an unknown attribute when validation runs. `toElement()` processes `this.prop` via direct property assignment (`el[name] = value`), validating existence and writability on the live element before assigning. `attributesArrayFromObject` skips `prop` (alongside `on`) so it never appears in the HTML attribute pipeline. Tag instances from any kensington module copy are accepted as valid content via duck-type markers: `ContentTag.prototype._isKensingtonTag = true` and `ContentTag.prototype._isKensingtonContentTag = true` (only `ContentTag` and its subclasses); `LiteralTag.prototype._isKensingtonTag = true`; `CommentTag.prototype._isKensingtonTag = true`. The local `isKensingtonTag(c)` helper checks `c._isKensingtonTag === true` and replaces all `instanceof ContentTag/LiteralTag/CommentTag` checks.
- `esm/tag-classes/void-tag.js`. Subclass for void elements (no closing tag, no content)
- `esm/tag-classes/literal-tag.js`. Wraps raw HTML strings passed via `.literal()` / `.unsafeLiteral()`; accepts a `Signal` . `toElement()` re-parses and replaces the element on each change. Constructed with `safe`, `validationLevel`, and `logger` from the Kensington instance. `toString()` and `toElement()` run the type check and (when `safe`) the `<script>` check via `showInvalid`. Invalid input renders nothing at `'off'`, logs at `'warn'`, throws at `'error'`. The signal effect is created via `_internalEffect` (so the rebuild path inside a parent's signal-content effect doesn't trip the `effect-in-effect` warning) and registered with `dom-tracker` via `trackForStop(startAnchor, ...)` so it stops when the surrounding subtree is removed. The `WeakRef` to the anchors is a secondary safety net for the case where the anchors are GC'd before the tracker sees the removal. The `trackForStop` callback also flips a `#reactiveStopped` flag on the LiteralTag instance, which `_isStaleAfterRemoval()` returns. A parent ContentTag's staleness walk uses this to know that the literal's effect is dead and a rebuild is required.
- `esm/tag-classes/comment-tag.js`. Wraps HTML comments created via `.inlineComment()`; accepts a `Signal` . `toElement()` updates `nodeValue` in place on each change. Constructed with `validationLevel` and `logger`. The `_normalize(raw)` helper checks the type and strips `--` sequences via `showInvalid`; it runs in both `toString()` and `toElement()` including on every signal update. The signal-text branch creates its effect via `_internalEffect` (matching `LiteralTag`) and registers `clearCache` via `addOnStop` so `#domElement` is nulled when the host element is removed. `_isStaleAfterRemoval()` returns `#domElement === null`, which a parent ContentTag's staleness walk consults to decide whether to rebuild.
- `esm/tag-classes/html-with-doctype-tag.js`. Subclass for `.htmlWithDocType()` that prepends `<!DOCTYPE html>`
- `esm/lib/reactive/warnings.js`. Owns `throttledError`, `throttledWarn`, `_resetWarningThrottle`, the `warnLastSeen` Map, and `WARN_THROTTLE_MS` (1000ms). Used by `signal.js` and `map-with-key.js` for repeated runtime diagnostics (loop detection, invalid usage, duplicate keys). Stack frames internal to Kensington are stripped via `filterStack` so the trace points to the caller's code.
- `esm/lib/reactive/ssr.js`. Owns the `ssrDepth` counter. Exports `_enterSSRMode`, `_exitSSRMode`, `isSSRMode`. `_enterSSRMode` is called by `renderForHydration` before invoking the user's component function and `_exitSSRMode` in its finally. When `isSSRMode()` returns true, `effect()` returns a no-op stub and `computed()` produces a frozen-value signal with no source subscriptions, so per-request rendering does not leak subscribers onto module-level signals that outlive the request.
- `esm/lib/reactive/hydration-scope.js`. Owns the per-mount hydration scope `Map` and the scope stack. Exports `_enterHydrationScope`, `_exitHydrationScope`, `_inHydrationScope`, `_disposeHydrationScope`, plus `getCurrentHydrationScope` (read accessor used by `signal()`). Each scope holds `{ signals: Map, computeds: Map }` keyed by user-supplied keys. Inside an active scope, `signal(initial, key)` and `computed(fn, key)` reuse instances across hot-swaps so user-visible values persist. Unlike `keyedRegistries` inside a computed, hydration scopes do **not** sweep unaccessed keys per render. Stable identity comes from the mount id, not from access tracking. Scopes are disposed only when the mount is removed via `_disposeHydrationScope`, at which point all signals and computeds in the scope are stopped.
- `esm/lib/reactive/signal.js`. `Signal` class with `.get()`, `.value`, `.set()`, `.stop()`, `.transform()`, `.toJSON()`, `.toString()`. Public exports `signal(initial, key?)`, `computed(fn, key?)`, `effect(fn)`. Internal exports `_internalEffect(fn)`, `_bindingEffect(sig, fn)`, `_internalComputed(fn)`, `_runMapWithKeyProbe(fn)`, `_isInReactiveContext()`. Plus `isKensingtonSignal(v)`. `isKensingtonSignal` duck-types via `_isKensingtonSignal === true` (set on `Signal.prototype`) so signals from a different kensington module copy are treated correctly. `signal(initial, key)` with a key scopes to a per-computed registry (`keyedRegistries` WeakMap) when called inside a `computed`, or to a hydration scope when `currentComputed === null` and `getCurrentHydrationScope() !== null`. Same key returns the same `Signal` across re-runs. `computed(fn, key)` with a key scopes to `keyedComputedRegistries` (WeakMap from outer computed to `{ computeds: Map<key, { versionSig, fnWrapper, inner }>, accessed: Set<key> }`). The same inner `Signal` is returned across outer re-runs. The fn closure is updated each run via a mutable `fnWrapper`, and a `versionSig` counter (a plain number signal) is incremented to trigger an inner re-run when the fn changes. The fn-wrapper approach avoids `Signal.set()` treating function arguments as updaters. Inside the keyed path the inner is created with `inComputedFn`, `currentComputed`, and `currentEffect` all cleared. The inner's wrapper fn also registers `keyedScopeOwners.set(currentComputed, owner)` on first entry so a sibling keyed signal read during the first run already sees the correct owner. `Signal.get()` subscribes the current effect (or computed update) to the signal. When the read targets a keyed primitive whose owner does not match `currentComputed` and the subscriber's own scope owner does not match either, it fires the `out-of-scope-reactive-reference` warning. Internal effects (`_isInternal` on the run function) skip the warning since their lifetime is tied to the DOM, not user-land scope. `Signal.set()` blocks writes on derived signals via the `derivedSignals` WeakSet plus a `derivedWriteDepth` counter (depth > 0 means we are inside the computed's own `update()`). Set snapshots `#subscribers` via spread before notifying because a computed subscriber's `update()` unsubscribes and re-subscribes during the same walk. `keyedRegistries` and `keyedComputedRegistries` use a per-run `accessed` Set, cleared at the start of `update()` and consulted at the end to stop entries whose keys were not touched. `keyedScopeOwners` maps any keyed inner back to its owner. Sleeping computeds preserve their registries; permanent `.stop()` clears them. Effects are built via `createEffect(fn, isInternal = false)`. `effect()` is the public form. `_internalEffect()` passes `isInternal = true`, which sets `run._isInternal = true` and causes (a) the `out-of-scope-reactive-reference` warning to be skipped for subscriptions made by this effect since DOM-binding effects are tied to the DOM, and (b) devtools to categorise the effect as a binding via `markNextEffectAsBinding(label)`. `_internalEffect` callers include `lifecycle.signalEffect` (through `_bindingEffect`), `LiteralTag`, `CommentTag`, and `map-with-key.js`'s keep-alive. `_bindingEffect(sig, fn)` is the single-signal fast path. It bypasses `track()` entirely (no `_cleanups` iteration, no `_reads` Set, no `currentEffect` dance) and calls `fn(sig.value)` on each notification. Subscribe and unsubscribe go through `sig._bindingSubscribe(run)` / `sig._bindingUnsubscribe(run)`. The two private helpers `#wakeIfSleeping()` and `#sleepOrNotify()` are shared between the binding path and the general `_unsubscribeFromRun(run)` path. `_internalComputed(fn)` pairs with `_internalEffect`. It clears `inComputedFn` and `currentEffect` around the `computed(fn)` call so the "computed-in-computed" entry warning (meant for user mistakes) does not fire when the library intentionally creates an inner computed. It also sets a module-level `nextComputedInternal` flag that `computed()` consumes to mark the new update closure `_isInternal = true`. The internal flag is necessary in addition to the cleared context. Reads inside the internal computed (typically of user-keyed signals/transforms passed to a tag attribute or class array) bypass the `out-of-scope-reactive-reference` warning because the same `!currentEffect._isInternal` gate is reused for both `effect` and computed-update subscribers. Without the flag, the class-list `_internalComputed`, attribute-composition `_internalComputed`, and `map-with-key`'s outer wrapper would trip the warning on every render of a row that combines keyed transforms with a class array. Used by `map-with-key.js`'s reactive path, its outer wrapper, `deriveClassList`, and attribute-list composition. `_runMapWithKeyProbe(fn)` swaps `currentEffect` to a probe object, clears `currentComputed` and `inComputedFn`, sets `inMapWithKeyProbe = true` and `suppressReactiveCheck = true`, runs fn, then restores. Returns `{ result, needsReactive }`. `needsReactive` is true if any signal was read (probe `_cleanups` non-empty) or if any `signal(initial, key)`/`computed(fn, key)` set `mapWithKeyProbeNeedsReactive = true`. On `needsReactive`, the probe's subscriptions are unwound before returning. `_isInReactiveContext()` returns `inComputedFn || currentEffect !== null`. Used by `mapWithKey` to fire the `mapwithkey-in-reactive` warning. Computed signals auto-dispose. When subscribers reach zero a `sleepFns` entry frees the source subscriptions; on a new subscriber `wakeFns` re-runs the fn and re-subscribes. `pendingSleep` defers sleep across the current flush so a re-subscribe in the same flush cancels it. Computed errors are caught and surfaced via `rethrowAsync` (`queueMicrotask` re-throw) so one bad computed does not abort the rest. `effect` runs are batched via `queueMicrotask` and processed by `flush()`. `MAX_EFFECT_LOOPS` (100) and `MAX_FLUSHES` (500) are loop-detection guards firing `sync-loop` and `async-loop` throttled errors. `.transform(fn, key?)` is implemented as `computed(() => fn(this.get()), key)` and is defined as a prototype assignment after `computed` to avoid a forward reference. A `computedCallSite` flag is set to `'transform'` around the call so the warning text inside `computed()` can be transform-specific. `.value` is a getter that returns `#value` directly without registering a subscription. `.toJSON()` returns `#value` directly so signals are transparent to `JSON.stringify`. `.toString()` calls `.get()` so template-literal coercion tracks dependencies in reactive contexts. `Signal.prototype.mapWithKey = mapWithKey;` is attached from `map-with-key.js`. Devtools instrumentation (`notifySignal*`, `notifyEffect*`) is imported from `devtools.js` and called at every lifecycle point. All calls are no-ops when devtools are not enabled.
- `esm/lib/reactive/map-with-key.js`. Exports `KENSINGTON_KEY` (the string `'_kensingtonKey'`), `stampKey(tag, key)`, and `mapWithKey(keyOrProp, mapFn)`. `KENSINGTON_KEY` is the internal property name stamped onto a tag returned by `mapFn`. The reconciler reads it via `itemKey(item)`. Storing the key in JS land (not as `data-key`) keeps the rendered HTML clean. `mapWithKey` returns an `_internalComputed` wrapper (not a plain `computed`). Using the internal form means the wrapper does not trip the `computed-in-computed` warning when `mapWithKey` is nested inside another `mapWithKey`'s `mapFn` (the documented recursive-tree pattern), and the wrapper's own reads of user-keyed signals/transforms inside the per-row tag tree do not trip the `out-of-scope-reactive-reference` warning. First sight of a key calls `buildEntry(item, mapFn)`. `buildEntry` runs `mapFn` under `_runMapWithKeyProbe`. If `needsReactive` is false (static path), the cache stores `{ tag, inner: null, keepAwake: null }` and subsequent renders return the same tag. Identical cost to a simple `Map` lookup. If `needsReactive` is true (mapFn read a signal or created a keyed primitive), the entry is upgraded to `{ tag: null, inner, keepAwake }` where `inner = _internalComputed(() => mapFn(item))` and `keepAwake = _internalEffect(() => { inner.get(); })`. The keep-alive holds a permanent subscriber so the outer wrapper's `track()` cycle cannot drop the inner to zero subs and re-run `mapFn` on the next `.get()`. When the inner re-emits a fresh tag (because a tracked signal changed), the reconciler's `tagNeedsRebuild` detects that `item.getDomElement() !== oldNode` and `rebuildNode` swaps the DOM in place via `preserve-state.js` (`captureState` + `restoreState`). The outer wrapper iterates the source array, looks up each key in the cache, calls `entry.tag === null ? entry.inner.get() : entry.tag` to get the current tag, stamps the key via `stampKey`, and returns the array. Keys whose items disappear are swept (their inner and keepAwake are stopped). Duplicate keys in the same render fire `throttledError('mapwithkey-duplicate-key', ...)` and the first item wins. Calling `mapWithKey` inside a computed or effect fires `throttledWarn('mapwithkey-in-reactive', ...)` because the whole per-key registry would rebuild on every outer re-run.
- `esm/lib/reactive/dom-tracker.js`. Shared `MutationObserver` that stops signal effects when their host element is removed from the DOM. A single observer on `document.documentElement` handles both direct removal and ancestor removal. `trackForStop(element, stop)` registers an element; the observer calls `stop()` when the element or any of its ancestors is removed. Called from `lifecycle.finalize` (for every signal-bearing `ContentTag`), `LiteralTag.toElement` (on the start anchor), and `CommentTag.toElement` (on the comment node). `stopTracked(element)` stops and deregisters an element's effects immediately. `stopRangeBetween(firstNode, endAnchor)` walks an entire sibling range with one `TreeWalker` pass and stops every tracked effect inside it. Used by reconcile's clear shortcut so 1000 row removals don't build 1000 walkers. Entries are stored in a `WeakMap` keyed by element so an element passed to `toElement()` and then dropped without ever being inserted into the document is not pinned by this module. `visit(node, fn)` walks the subtree via `document.createTreeWalker` with a mask of `SHOW_ELEMENT | SHOW_COMMENT`, calling `fn(el, entry)` only for the elements that have a WeakMap entry. The walker iterates the actual descendants (a few elements per removed row), which is dramatically cheaper than iterating every tracked entry in the whole document for every mutation record. When the removed node itself is tracked, descendant non-element nodes are skipped so that comment-anchor entries owned by LiteralTag and CommentTag are not collateral damage of a persist parent's pause-on-removal cycle. The observer callback guards `stopRemoved(node)` with `if (!node.isConnected)`. A node removed and immediately reinserted in the same mutation batch will be connected again when the observer fires, so its effects must not be stopped. A one-shot `hasAnyTracked` latch short-circuits the observer when nothing has ever been registered. `notifyDomTrack()` and `notifyDomUntrack()` are called from `getOrCreate` and `deleteEntry` to keep the devtools DOM-tracked element count current. A small `stopOne(element, entry)` helper is shared by `stopRemoved`, `stopRangeBetween`, and `stopTracked` so the "clear-and-fire" sequence lives in one place.
- `esm/lib/reactive/lifecycle.js`. Owns the per-element lifecycle for signal effects and connect/disconnect callbacks. `createLifecycle({ element, persist })` returns a `lifecycle` object used by `ContentTag.toElement()`. ContentTag allocates a lifecycle lazily on first signal binding (via an `ensureLifecycle` arrow with `??=`); a fully static tag with no signals, no events, no callbacks, and no `persist` never creates one. `lifecycle.signalEffect(sig, apply, label)` creates a lightweight binding effect (via `_bindingEffect`) that applies a signal value to a DOM element. It calls `markNextEffectAsBinding(label)` before effect creation so devtools categorises it as a DOM binding with the given label (attribute name, `prop:X`, or `'(content)'`), then calls `notifyEffectElement(eff._devId, element)` to associate the effect with its element for element highlighting in the devtools DOM tab. Effects are stored in an `effects` array on the lifecycle. The stop chain registered by `finalize` iterates the array and dispatches once, choosing `eff.pause()` or `eff.stop()` based on the captured `persist` flag, rather than allocating one `pauseOrStop` closure per effect.
- `esm/lib/reactive/devtools.js`. Implements the `window.__KENSINGTON_DEVTOOLS__` hook. `enableDevtools()` activates the hook once; subsequent calls are no-ops. The hook object (`hook`) exposes `signals` (Map), `effects` (Map), `bindings` (Map), `domTrackedCount`, and an `on(event, cb)` / `off(event, cb)` / `_emit(event, data)` event bus. Signal IDs and effect IDs are monotonically increasing integers assigned by `notifySignalCreate` and `notifyEffectCreate`. `signalGcRegistry` (FinalizationRegistry) removes devtools entries for signals that are garbage-collected without an explicit `.stop()` call. `pendingZeroSubscribers` (Set) holds signal IDs scheduled for removal via `notifySignalZeroSubscribers`; a `queueMicrotask` fires the removal unless a re-subscription cancels it first (supports drag-reorder pause/resume without losing signals from the panel). `computedSigs` (WeakSet) records which signals were created via `computed()` so `notifySignalWake` can restore `isComputed: true` when a sleeping computed is re-added to the map. `markNextEffectAsBinding(label)` sets a one-shot flag so the next `notifyEffectCreate` call stores the effect in `hook.bindings` instead of `hook.effects`. All exported `notify*` functions are no-ops when `enabled` is false.
- `esm/lib/reactive/reconcile.js`. DOM reconciler for signal arrays. Matches nodes by an internal `KENSINGTON_KEY` property carried on tag instances produced by `signal.mapWithKey`. The reconciler reads that property via a `nodeKeys` `WeakMap` keyed on the live DOM node, populated when a fresh node is inserted. The user's rendered DOM is left clean of internal bookkeeping. Stable tag instances passed directly (not via `mapWithKey`) get the tag itself as an implicit key via the `_isKensingtonTag === true` fallback in `itemKey()`. Truly unkeyed items always build fresh DOM. `tagNeedsRebuild(item, node)` is the rebuild gate. It returns true when the item is a kensington tag whose `getDomElement()` returns something other than the live node, which is how the reconciler detects a `mapWithKey` reactive re-emit (the per-key inner computed produced a fresh tag whose own DOM does not back the live node). `rebuildNode(parent, oldNode, item, key)` builds the new DOM via `item.toElement()`, captures user-visible state from `oldNode` via `preserve-state.js#captureState`, swaps via `parent.insertBefore(fresh, oldNode)` + `oldNode.remove()` (so `dom-tracker`'s observer stops the old effects), then `restoreState(fresh, state)`. Each of the four bidirectional branches and the slow keymap path call `tagNeedsRebuild` before reusing the matched node, falling through to `rebuildNode` when it returns true. **Clear fast path**: when newItems is empty and the range between anchors is non-empty, `stopRangeBetween(firstChild, endAnchor)` tears down all tracked effects in one TreeWalker pass and a single `Range.deleteContents()` removes the DOM in one operation. **Bidirectional pass**: Vue 2 / Inferno style. Each iteration checks four cases (prefix match, suffix match, head-moved-to-tail, tail-moved-to-head) against the current `oldStart`/`oldEnd` of an `oldChildren` snapshot Array and `newStart`/`newEnd` of the `items` array, costing at most one DOM mutation per iteration. The hot paths (no change, swap, contiguous insert, contiguous remove, head-to-tail rotation, tail-to-head rotation) finish here without building a keymap. The js-framework-benchmark swap test lives entirely in the "tail-to-head" branch on iteration 3 and the "head-to-tail" branch on iteration 4, then matches prefix/suffix for the remaining ~996 iterations with no DOM mutations. **Pure-insert tail**: when `oldStart > oldEnd`, append remaining new items before the trailing fence (`oldChildren[oldEnd+1]` or `endAnchor`). **Pure-remove tail**: when `newStart > newEnd`, drop remaining old children. **Slow path / keymap**: when none of the four cheap cases match, build a `Map<key, oldIndex>` from the remaining old range and walk the new range right-to-left, inserting before a running `insertRef` that starts at the trailing fence. Reused old nodes are marked `oldChildren[i] = null` so the final removal sweep skips them. The keymap branch also calls `tagNeedsRebuild` and routes through `rebuildNode` when a matched key has a fresh tag. Real-world workloads (sorts, filters, single edits) finish above the slow path. There is no in-place patching path. A key always resolves to a stable cached tag instance (produced by `mapWithKey`) or to a freshly-built node, so the previous `syncNode`, snapshot, and signal-mismatch-replace paths are gone. `valueEqual`, `snapshotMatches`, `snapshotHasSignalRefMismatch`, `element-listeners.js`, and `staticProps` are no longer used here. `itemToNode(item)` calls `item.getDomElement?.() ?? item.toElement()` for tag instances so per-key cached tags return their already-built element. `isRenderableItem(item)` skips `null`/`undefined`/`false`/`true`/`''`. `filterRenderable(items)` strips non-renderable items upfront so the bidirectional pass can index by position; the hot path returns the input array directly with no allocation. `flattenIfNeeded(items)` only allocates a flat buffer when the input contains a nested array; the common (already flat) case returns the input array directly.
- `esm/lib/reactive/preserve-state.js`. Captures and restores user-visible DOM state across two call sites. `reconcile.js`'s `rebuildNode` uses it when a `mapWithKey` per-key inner re-emits a fresh tag, swapping the row's DOM in place. HMR's component-replacement path in `hydration.js` uses it when `hmrReplaceComponent` re-renders a live mount. `captureState(root)` walks the subtree and records the focused element's path (child-index array from `root`) and its text selection range if applicable, `scrollTop`/`scrollLeft` on every scrollable node, `value`/`checked`/`indeterminate` on `INPUT`/`TEXTAREA`, `value` on `SELECT`, and `open` on `DETAILS`/`DIALOG`. `restoreState(root, state)` applies each entry by resolving the path on the new subtree and assigning the captured properties. Positional matching assumes the tree shape is identical between renders, which holds when only signal references differ. Mismatched positions silently drop their state. State that lives only in the element instance and cannot be captured (IME composition, CSS animations in flight, pointer capture, canvas bitmap, iframe contents, web component instance state, third-party listeners) is lost on replacement. Documented as a tradeoff.
- `esm/lib/util/filter-stack.js`. Strips Kensington-internal stack frames from an `Error` object so throttled warnings and validation errors point to the caller's code. In Node.js it detects the library path via `import.meta.url` (a `file:` URL points at the real `esm/` directory on disk) and strips frames matching that path. In a browser bundle, kensington and user code share the bundle URL, so any URL-based filter would also strip every user frame and warnings would surface with only `forEach@[native code]` left. The filter therefore preserves the full stack whenever it cannot reliably distinguish internal from external frames (browser bundle, IIFE bundle, or any environment where `import.meta.url` is missing or points at the bundle itself). Shared by `show-invalid.js` and the `throttledError` / `throttledWarn` functions in `signal.js`.
- `esm/lib/`. Other utilities: attribute string/array builders, indentation, content stringification, `he` encoder wrapper, camelCase↔kebab-case conversion

### Error policy

**Never throw when `validationLevel` is `'off'`.** Production deployments run with `'off'` for performance. An unexpected throw can take down a server or break a user-facing page. Invalid input at `'off'` level must be silently skipped. Render nothing, omit the attribute, filter the content item. Rather than crashing. Use `showInvalid(message, this.validationLevel, this.logger)` for every validation check: it does nothing at `'off'`, logs at `'warn'`, and throws at `'error'`. The only exceptions are hard invariants that indicate a programming error at library setup time (e.g. an invalid `validationLevel` value passed to the constructor, a non-string `tagName` passed to `createCustomTag`). Those throw unconditionally because they can only be caused by incorrect integration code, not by runtime data.

### Tag creation flow

`Kensington.createTag(tagName, allowedAttributes, Klass, options)` returns a closure. When called, that closure validates arguments, instantiates the appropriate tag class (`ContentTag`, `VoidTag`, etc.), runs attribute validation if `validationLevel !== 'off'`, and returns the instance. Tag methods are bound in the constructor so they can be destructured.

### Options handling

- Nested objects flatten to kebab-case: `{ data: { bs: { toggle: 'collapse' } } }` → `data-bs-toggle="collapse"`
- camelCase keys convert to kebab-case: `{ dataBsToggle: 'collapse' }` → `data-bs-toggle="collapse"`
- Boolean attributes are included when `true`, omitted when `false`
- `style` accepts a plain object: `{ style: { backgroundColor: 'red', zIndex: 2 } }` → `style="background-color: red; z-index: 2"`. camelCase keys are converted to kebab-case (CSS property names are always kebab-case; camelCase is only the JS DOM convention for `element.style` properties. This applies to SVG styles too); `null`/`undefined`/`false` values are silently omitted; other non-string/number values are flagged by validation.
- `data-*` and `aria-*` namespaces are always allowed; additional namespaces (e.g. `hx` for htmx) are passed via constructor
- SVG elements accept all CSS properties as presentation attributes (per the SVG spec). In `esm/attributes.js` a single `svgPresentationAttributes` export object is spread into each SVG element's attribute object to avoid duplicating ~744 entries per element. In `types.d.ts` a single `SvgPresentationAttributes` type is intersected into each SVG element's attribute type for the same reason.
- Event handler attributes (`onclick`, `oninput`, and all `on*`) accept `[String, Function]`. Functions are valid at tag creation and wired via `addEventListener` in `toElement()`. In `toString()`, function values cannot be serialized. They are omitted, with the `handleFunctionValues` callback in `attributesStringFromObject` invoking `showInvalid` at that point rather than at creation time.
- `prop` key: accepts a plain object mapping DOM property names to static values or signals. Applied in `toElement()` via `el[name] = value` (property assignment, not `setAttribute`). Property existence and writability are checked against the live element at render time via `isPropWritable()`. Silently ignored in `toString()`. TypeScript types are derived from `HTMLElementTagNameMap`/`SVGElementTagNameMap` via the `PropFor<Tag>` utility type in `types.d.ts`. Known writable properties are typed against the element's DOM interface. Arbitrary string keys (expandos) are also accepted via an index signature (`{ [key: string]: unknown }`).

### HMR (`esm/vite/` and `esm/lib/render/hydration.js`)

The `./vite` subpath export ships `kensingtonHmr`, a Vite plugin that wires transparent HMR for component files. It is `apply: 'serve'` only; production builds skip the transform entirely. `acorn` and `magic-string` are declared as **optional peer dependencies** of kensington. They are loaded lazily inside the plugin so installing kensington without them is harmless. The plugin throws a clear install hint only when it is actually invoked.

- `esm/vite/index.js`. The `kensingtonHmr({ include })` plugin. `include` is required and accepts a glob string, an array of glob strings, or a callback `(server) => string | string[] | null`. The callback form receives the Vite dev-server reference, which lets adapters like kensington-dev-server read globs from late-binding runtime config (stashed on the dev-server reference via a well-known symbol). Static glob/array forms are equivalent to a callback that returns them. For each matched file the plugin parses the source to an AST and rewrites every top-level component export to flow through `__kInstrument(name, fn)`. An `import.meta.hot.accept` block is appended that calls `hmrReplaceComponent(name, mod.<access>.__kFn)` on save. Detected forms: named function/arrow/const exports, default function (named or anonymous, falling back to the file basename), `export default NAME` re-exports of a local declaration, and `export { NAME, ... }` specifier lists. Unsupported shapes (e.g. `export default <complex expression>`, `export { NAME } from './other.js'`) silently keep no-HMR behaviour.

- `esm/lib/render/hydration.js` (HMR additions). Exports `__kInstrument(name, fn)` and `hmrReplaceComponent(name, newFn)` alongside the existing `renderForHydration` and `registerComponents`. `__kInstrument` returns a wrapper whose `.__kFn` property exposes the original function (so the Vite plugin's accept handler can read it back unwrapped). The wrapper preserves `fn.name` via `Object.defineProperty` so server-side `renderForHydration(counter, state)` still derives the right component name from `fn.name`. On the client, the wrapper enters a hydration scope keyed by a fresh mount id, calls the original fn, and intercepts the returned tag's `toElement` so the live element is stamped with `data-k-mount-target=<mountId>` and recorded in a module-level `liveInstances` map. SSR (`isSSRMode()`) and re-entrant calls (`_inHydrationScope()`) skip instrumentation. `recordInstance` and `dropInstance` maintain the per-name `Set` of `{ mountId, mountNodes, fn, state }`. `hydrateComponent` (the path taken by `registerComponents`) also enters a hydration scope keyed by the SSR mount id, stamps the live nodes with `data-k-mount-target`, and records the instance with the same shape so hot-swaps work uniformly for SSR-hydrated and client-only components. `hmrReplaceComponent(name, newFn)` first unwraps `newFn.__kFn` if present, updates the `componentRegistry` (so newly inserted SSR mount markers pick up the latest function), then walks every live instance under the name. For each live instance it captures user-visible DOM state via `preserve-state.js#captureState`, re-renders inside the same hydration scope (so `signal(initial, key)` and keyed `computed`s reuse their existing instances and state survives), replaces the live nodes in place, and restores state. Disconnected instances are pruned and their hydration scopes disposed via `_disposeHydrationScope`. Effects on the discarded DOM are stopped automatically by `dom-tracker`'s `MutationObserver`.

- Hydration scope plumbing in `signal.js`. Inside an active hydration scope (see `hydration-scope.js`), `signal(initial, key)` with `currentComputed === null` looks up the per-scope `signals` map by key and returns the existing instance if any. New signals are created with `suppressReactiveCheck = true` so the "signal inside computed" warning does not fire (we are not inside a computed; we are inside a hydration scope). Across a hot-swap the same scope id means `signal(initial, key)` and `computed(fn, key)` reuse their existing instances, so user-visible values persist.

### CLI. Html-to-kensington

`bin/html-to-kensington.js` is the `kensington` binary (set in `package.json` `"bin"`). It reads HTML from a file argument, stdin (pipe/redirect), or interactive terminal paste using bracketed paste mode, then converts it to Kensington code via `bin/lib/convert-html.js`.

- `bin/lib/convert-html.js`. Top-level converter; uses `parse5` to parse HTML/fragments, then delegates per-node to `node-to-code.js`
- `bin/lib/node-to-code.js`. Converts a single parse5 node to a Kensington method call string
- `bin/lib/attrs-to-code.js`. Converts a parse5 attribute list to a JS object literal string; groups `data-*`/`aria-*` prefixes, expands `style`, converts kebab-case to camelCase
- `bin/lib/formatter.js`. Detects ESLint or Prettier in the cwd; reads `max-len`/`printWidth` for line-breaking and runs the formatter over the output
- `bin/lib/read-html.js`. Reads HTML from stdin (TTY: bracketed paste mode; non-TTY: stream)
- `bin/lib/clipboard.js`. Copies output to the system clipboard (`--copy` flag)
